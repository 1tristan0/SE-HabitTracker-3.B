==== Modelle im Schema
* Enums: `animal_type` (hund/katze/hamster/wurm), `animal_mood` (gluecklich/traurig)
* `habits_table`
** Primärschlüssel `id` (String mit `uuid()` Default)
** Felder u.a. `userId` (FK auf `users.id`), `habit_name`, `description`, `start_date`, `streak` (BigInt), `last_break`, `last_checked`, `prev_last_checked` (Array)
* `users`
** Primärschlüssel `id` (String mit `uuid()` Default)
** Felder für Tier-Status: `animal_type`, `animal_mood`
** Relation: 1-n zu `habits_table`

==== Generierung & Migrationskommandos
Befehle innerhalb der Shell des Backend-Containers ausführen, nicht im Hostgerät:

* Client generieren (automatisch über Dockerfile oder in der Container Shell): `npx prisma generate`
* Schema validieren: `npx prisma validate`
* Migration erzeugen (falls benötigt): `npx prisma migrate dev --name <name>` (setzt lokale DB voraus)
* Schema ohne Migration in die DB pushen (leere DB): `npx prisma db push`
* Migrations chronologisch auf DB anwenden: `npx prisma deploy`
* Migrations liegen in link:../../src/backend/prisma/migrations[backend/prisma/migrations]

==== Nutzung im Code
* Beispiel-Query: link:../../src/backend/src/routes/habits.js[backend/src/routes/habits.js] Route `/api/habits` ruft `prisma.habits_table.findMany()` auf und serialisiert `streak`/Dates für JSON-Ausgabe.
* BigInt-Hinweis: Node JSON kann BigInt nicht serialisieren – deshalb werden `streak`-Werte in Numbers gewandelt (siehe `serializeHabit`).

==== Umgebungsvariablen
* `DATABASE_URL` muss vor Prisma-Aufrufen gesetzt sein.
** Lokal: link:../../src/backend/.env[backend/.env]
** Docker-Dev: `backend/.env.local` (siehe `docker-compose.dev.yml`)
** Docker-Prod: `backend/.env.production` (falls vorhanden, siehe `docker-compose.prod.yml`)
* Hinweis: `prisma.config.js` nutzt `env("DATABASE_URL")` aus Prisma Config; die `.env` wird nicht automatisch geladen, wenn die Umgebung nicht gesetzt ist.

==== Troubleshooting
* Schema-Änderungen greifen nicht: neu generieren, ggf. Migration/Push auf DB, eventuell fehlerhafte Migration zuvor erstellt die noch die "Pipeline" blockiert (aktuelle Migration ist gar nicht der Fehler) -> reset auf init_migration 
* Verbindung schlägt fehl: `DATABASE_URL` prüfen, Netzwerkzugriff zum DB-Host sicherstellen
* Wir arbeiten mit Prisma 6.x, darauf achten, dass nicht durch `npm install` auf Version 7.x geupdatet wurde
