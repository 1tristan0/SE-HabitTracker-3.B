== Docker Guide
=== Übersicht Containerstruktur

* **gewohnheitstier-backend**
  - Basierend auf `node:20-bullseye`
  - Enthält Express-Server, REST-API und Business-Logik

* **gewohnheitstier-frontend**
  - Basierend auf `node:20-bullseye`
  - Enthält React-SPA (CRA)

Die DEV-Umgebung kommuniziert dabei mit der lokalen Instanz con Supabase, während die PROD-Umgebung mit der Cloud-Instanz kommuniziert.

=== .env - Dateien
Die .env-Dateien setzte den nötigen Umgebungskontext via der entsprechenden Variablen.
==== env (Frontend)
```
REACT_APP_API_BASE_URL=http://localhost:3001
```
==== env.local
```
NODE_ENV=development
# Mac 
#DATABASE_URL="postgresql://postgres:postgres@host.docker.internal:54322/postgres"
# Linux 
DATABASE_URL="postgresql://postgres:postgres@172.17.0.1:54322/postgres"

# Mac
#SUPABASE_URL=http://host.docker.internal:54321
# Linux
SUPABASE_URL=http://172.17.0.1:54321

SUPABASE_ANON_KEY=****
PORT=3001
```
==== env.production
```
NODE_ENV=production
DATABASE_URL="postgresql://<user>.<project_ref>>:g<password>@aws-0-eu-central-1.pooler.supabase.com:5432/postgres"
SUPABASE_URL=https://<project_ref>.supabase.co/
SUPABASE_ANON_KEY=****
PORT=3001
```
=== Nutzung

==== Projekt starten
[source,bash]
----
docker compose up -f docker-compose.yml -f docker-compose.dev.yml up --build
----
bzw.
[source,bash]
----
docker compose up -f docker-compose.yml -f docker-compose.prod.yml up --build
----
Dadurch werden beide Container gebaut und gestartet.  
Der Client ist anschließend unter `http://localhost:3000` und der Server unter `http://localhost:3001` erreichbar.

==== Projekt stoppen
[source,bash]
----
docker compose down -v
----
`-v` entfernt dabei alle erstellten Volumes. Wichtig wenn Änderungen an den Nodemodules vorgenommen wurde.

==== Logs anzeigen
[source,bash]
----
docker compose logs -f
----

==== Vorteile

* Einheitliche Entwicklungsumgebung für alle Teammitglieder
* Trennung von Entwicklung und Produktion
* Ermöglicht gleichzeitige Arbeit an Front- und Backend
* Leicht portierbar
* Isolation der Abhängigkeiten

Durch die Dockerisierung ist das Projekt *Gewohnheitstier* plattformunabhängig, reproduzierbar und teamfähig.  
Alle Entwickler können ohne komplexe Setups sofort starten.
